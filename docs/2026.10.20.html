画图时间从 70% 砍到 30%：硅谷设计师早就换方法了

优设梳理一线团队做法：Anthropic 的 Nate Parrott 把设计规范喂给 Claude，一次并行分叉 12 个真实可点的 HTML 原型（演化为 Claude Design）；Cursor 的 Ryo Lu 则只用约 20% 时间理清概念模型，随后直接在代码库搭可交互原型，用 Cursor 微调组件、间距与动效，砍掉「标注—走查—还原度扯皮」。

下一版需求先问自己：这周是在「手搓静态高保真」，还是在「语言发散多方案 + 真实材料验证」？能交互的 HTML/代码原型，比再完美一张 Figma 更难被 AI Demo 替代。

AI 味到底是什么？从文案到 UI，拆解 4 类典型特征

《设计 100 问》长文提醒：过度依赖 AI 写作后，风格会被均摊成「正确但不讨喜」。作者结合设计交付现场，把「AI 味」拆到文案腔调、结构套路、UI 模板感与审美均质化等可识别特征，并主张人机结合才是主路径——纯手搓负责核心创意，AI 负责延展与提效，纯 AI 量产则极易沦为检索污染。

评审或自查时列一张「AI 味检查表」：有没有万能过渡句、蓝紫渐变壳、无信息装饰插画、对谁都正确的观点？改掉这些，比再换一个生图模型更有效。

Anthropic 研究 Agent 代谈规则：砍价、纠纷时何时必须问人

极客早知道援引《金融时报》：Anthropic 与法律专家讨论 AI Agent 代表用户谈判时的行为规范——利益争取到什么程度、何时征求确认、面对其他 Agent 是否默认对方可能操纵；并探讨用签署文件明确代理权限、目标与边界。尚处规则研究，未上线自动谈判服务。

设计「Agent 可代操作」流程时，把不可逆动作（付款、签约、对外承诺）做成结构化审批卡，而不是埋在聊天里的一句「好的」；权限要写清一次性 / 本任务 / 限时 / 长期四档。

Meta Thin Orchestrator：让路由少干活，Agent 反而更可靠

Meta 工程博客（10/19）介绍 Thin Orchestrator 思路：有时把全部知识塞给路由型 Agent 反而不对——给路由器减负、把职责下沉到更专的子能力，能提升智能体可靠性。该文来自 Muse 相关工程实践，与「大而全的单一编排」形成对照。

搭设计/运营 Agent 时，别让一个「总管」同时懂规范、找素材、改文案、发版；拆成专责子 Agent + 薄编排，失败时也更好定位是哪一步坏了。

量子位报道谷歌开源 Harness²：针对真实任务「无标准答案、改完易过拟合」两难，用任务级 Propose–Probe–Compose 对照实验候选脚手架，再用改进级递归把有效改动沉淀进 EXPERIENCE.md 经验库；已支持 OpenCode 与 Codex。

审美好就能做好设计？设计师最容易陷入的 3 个误区

文章把「审美」从美育话题拉回职场沟通：别人问「为什么设计成这样」多数时候是在要解释或方案，未必是攻击；审美难以量化时，别用它当挡箭牌；在 AI 冲击下宣称「技术其次审美最重要」若不能落到可比较的目标与约束，帮不了决策。

下次被追问时先停三秒：对方有没有恶意、想听的是设计理由还是业务取舍？用「目标—约束—备选」回答，比捍卫「我的审美」更专业。
