Tessl Verifiers：用仓库规则审核每次 Agent 改动

Tessl 发布 Verifiers：规则以 JSON 放在仓库内，每次代码变更由 LLM judge 逐条 pass/fail，可像 lint 一样跑在本地、pre-commit 或 CI。

设计系统约束也可写成「可机读规则」：色板、间距、组件命名进仓库，让 Agent 改 UI 时自动对表，而不是事后人工肉眼扫。

Google：系统评测 AI 智能体，告别 vibe check

Google Developers Blog 给出智能体评测实践：只在终端跑几个提示词无法发现重试死循环、工具参数幻觉等隐性失败，需要可复现的评测集与失败分类。

给设计/产品 Agent 建一份「必过场景清单」（含故意刁难的边界 case），比凭感觉说「这次生成不错」更能指导迭代。
